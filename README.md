# 디시 아카이브

디시인사이드 실시간 베스트의 공개 본문을 개인 열람용으로 보관하는 비공식 아카이브입니다.

- 첫 수집: 실베 **목록 1~10페이지**의 일반 글 전체(공지·광고 제외).
- 이후: 매일 **방콕 10:00 / 한국 12:00 / UTC 03:00**에 신규 글 수집 예약. GitHub 사정으로 실행이 지연될 수 있습니다.
- 기존 개드립 아카이브와 같은 다크 템플릿, 20개씩 목록, 전체 제목 검색, 읽은 글 표시를 사용합니다.
- 본문과 DC 이미지·지원 영상/음성, 원문 댓글·답글·디시콘·이미지 댓글을 보관합니다. 로그인이나 댓글 작성 기능을 새로 제공하는 것이 아니라 원문 댓글의 읽기 전용 스냅샷입니다.
- 댓글은 공개 페이지가 사용하는 `/board/comment/` 읽기 요청을 통해 페이지를 끝까지 확인합니다. 원문 오류와 실제 댓글 0개를 구별하며, 실패 시 이전 댓글을 보존하고 재시도 대상으로 남깁니다. 기존 글의 댓글 보강도 매일 실행됩니다.
- iframe/외부 임베드 영상은 안전한 원본 링크로 남깁니다.
- 파일당 12 MiB를 초과하는 미디어, 외부 미디어 또는 다운로드 실패 미디어는 원본 링크를 유지하며 해당 글에 안내합니다.
- 로그인/성인 인증/차단을 우회하지 않습니다. 접근 가능한 공개 글만 처리합니다.
- 권리는 원저작자에게 있으며 원문 링크를 각 글에 표시합니다.

## 안정성

일시적인 HTTP 오류에는 지수 백오프로 재시도합니다. 발견한 글 목록을 먼저 기록하고, 글마다 로컬 진행 상황을 저장하며, 20글 단위로 GitHub에 묶어 반영합니다. 실패한 글은 `pending.json`에 남아 다음 실행에서 다시 수집합니다. 일부 실패가 있어도 성공한 글은 게시하고 실행은 실패로 표시합니다. 수집이 끝나면 별도 Pages 워크플로가 배포합니다.

빈 응답을 반환한 미디어는 즉시 추가 재시도하고, 계속 실패하면 다음 실행에서 해당 글을 다시 수집합니다. 용량 제한 및 외부 미디어 원본 유지 항목은 이 재시도 대상에서 제외합니다.

HTML만 Pages로 배포하고 미디어는 해당 커밋의 GitHub 원본 파일로 연결합니다. 저장소 크기·GitHub 대역폭·호스팅 정책에는 한계가 있어 무제한 영구 운영을 보장하지 않습니다. 공개 재배포 범위와 원사이트 이용 정책을 확인해서 사용하세요.

## 실행

Python 3.11 이상에서 `python -m pip install -r requirements.txt` 후 `python archiver.py --pages 10 --publish`. 저장소 push 권한이 필요합니다. 개인 PC가 꺼져도 매일 GitHub Actions에서 실행됩니다.

테스트: `python -m unittest discover -s tests -v`.

## 댓글 보강과 화면 적용

- 저장된 본문에 템플릿 재적용(원사이트 재다운로드 없음): `python archiver.py --retheme --publish`
- 누락 댓글·디시콘 보강: `python archiver.py --backfill-comments --workers 3 --publish`
- 시범 3글만 검증: 위 명령에 `--comments-limit 3` 추가.
- `comments/<글ID>.json`에는 표시용 닉네임·본문·날짜·댓글/상위 댓글 번호만 보관합니다. 작성자 계정 ID, IP 주소, 세션·페이지 토큰은 저장하지 않습니다.
- 현재 소스 서버가 오류일 때 화면에 '댓글 보관 대기'가 표시될 수 있습니다. `comments-status.json`이 미완료 글을 기록하며 정상화 후 다음 실행에서 보강합니다.

## 용량 관리

기존 `dogdrip-archive`의 미디어 제외 Pages 배포 및 `dogdrip-archive-old`/`cold-storage.json`의 분리 보관 방식을 확인해 적용했습니다. Pages 배포는 `posts`만 sparse checkout하고 미디어는 보관 커밋으로 연결합니다. 검색에 필요한 `archive.json`도 같이 배포합니다.

`capacity-report.json`은 실제 미디어 용량과 여유 디스크를 기록하며, 활성 미디어 2 GiB부터 경고합니다(서비스의 공식 한도가 아니라 사전 점검 기준). 글·첨부파일 자동 삭제나 Git 이력 강제 재작성은 하지 않습니다. 별도 보관소를 사용하려면 파일 복사와 해시·공개 접근을 검증한 다음 `media-locations.json`에 아래처럼 불변 커밋을 연결할 수 있습니다. **비공개 저장소는 공개 사이트의 이미지 서버로 사용할 수 없으며**, 원본을 지우기 전에 검증이 필요합니다. 기본 Actions 토큰은 다른 저장소 생성·쓰기를 할 수 없으므로, 자동 이관을 활성화하려면 별도의 적절한 권한 설정이 필요합니다.

```json
{
  "assets/123/example.jpg": {
    "repository": "pjk3864/dcinside-archive-media-001",
    "commit": "검증된 40자리 Git 커밋 SHA",
    "path": "assets/123/example.jpg"
  }
}
```
